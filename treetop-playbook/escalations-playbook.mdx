Escalations are the agents asking for human judgment. They're the work waiting on you each shift. Resolving them quickly keeps the pipeline moving and keeps SLAs green.

## How to read an escalation

Each escalation surfaces in the [Command Center](/recruiter/command-center) with:
- **Reason** — short label describing the issue.
- **Source agent** — which agent flagged it.
- **Candidate context** — name, role, current scheduling status, assigned recruiter.
- **Full explanation** — the agent's account of what happened and its recommendation.
- **SLA deadline** — if configured.

Click in to see the candidate's full drawer, take the action that matches the reason, then **Mark Resolved** with a short resolution note. Resolution notes are how your team learns from the case — and how the agents improve over time.

## Common types, fast paths

For each reason code, the [Escalations](/recruiter/escalations#how-to-resolve-by-reason) page has the exact action. The patterns:

- **Ambiguous screening** → override on the Screening tab.
- **Unclear candidate reply** → read the thread, send operator guidance or message directly.
- **Calendar issue** (`no_slots_found`) → fix the conflict in Google Calendar, then re-trigger scheduling.
- **Weekend / after-hours request** → decide whether to honor it. If yes, send guidance permitting the off-hours slot. If no, message a daytime alternative.
- **Delivery failure** → verify the candidate's contact info, update if wrong, re-trigger outreach.
- **Repeat no-show** → default is reject. Override the recommendation if you disagree.

## Resolve, then decide what's next

After resolving the escalation, decide whether the agent should resume or whether you want to keep the thread human-owned. Resolving the escalation alone doesn't dismiss the agent — see [Escalations → Escalation vs. human-owned](/recruiter/escalations#escalation-vs-human-owned).

For the full reason-code map and resolutions, see [Escalations](/recruiter/escalations).
