## August 2026

### New features

- **Cancel a batch of candidates in one action.** Select several applications in the applicant list and cancel them together instead of one at a time. Each candidate gets the right message for their situation, and if one of them writes back afterwards the agent answers rather than leaving the reply unattended. See [Applicants](/recruiter/applicants).
- **Escalations that miss their deadline now surface on their own.** Every escalation carries a response deadline, and a sweep now raises the ones that pass it. Before this, a stalled escalation stayed invisible until someone happened to notice — in one case a candidate waited nearly three days. See [Escalations](/recruiter/escalations).
- **Candidate-level escalations are fully actionable.** When a candidate has several applications assigned to different recruiters, their escalation used to appear in Command Center as a card you could not open or clear. It now opens a full detail view with the candidate's context and every related application, so you can act on it and hand the candidate back to the agent. See [Command Center](/recruiter/command-center).

### Updates

- **The agenda shows where the interview is.** The Reminder column is replaced by Location, which shows the job's city, state, and ZIP. Reminder state is still visible on the candidate's timeline. See [Interview Agenda](/recruiter/agenda).
- **The agenda opens filtered to you.** It now defaults to the signed-in recruiter's interviews instead of everyone's. Switch to another recruiter or to all recruiters with the filter. See [Interview Agenda](/recruiter/agenda).
- **Reminder timing follows the booking day.** A candidate who books on the day of the interview now gets only the ten-minute reminder. A candidate who books the evening before no longer gets a morning-of reminder. See [Follow-up policy](/recruiter/follow-up-policy).
- **Screening decisions have to agree with their own reasoning.** A screening result that advances a candidate while the reasoning says the opposite is now rejected instead of saved, and a decision that overrides a screening rule has to name the rule it overrides. See [Screening](/recruiter/screening).

### Bug fixes

- **No more double replies to back-to-back messages.** When a candidate sent two texts within a few seconds, both could trigger a reply, and the second one answered a message the agent had already handled. A run that has been superseded by a newer message now stops instead of replying. See [Communication](/recruiter/communication).
- **Follow-ups no longer go out early.** Fixed a case where a follow-up snapped to the candidate's preferred time of day and sent before the waiting period had actually elapsed. See [Follow-up policy](/recruiter/follow-up-policy).
- **Follow-ups no longer point at times that have passed.** Interview slots the agent offered earlier are dropped from its context once they expire, so a nudge can't ask a candidate to confirm a time that is already gone.
- **The scheduling agent records the times it offers.** After proposing interview times it did not always save the interview request or move the scheduling status, so the application looked untouched.
- **An escalation always leaves the candidate with a reply.** Fixed a case where the agent could escalate to a person and send the candidate nothing at all.
- **Escalation handoffs no longer strand a candidate.** Messages that arrive during an active escalation now come back to a human, escalations carry the application they belong to, and closing out one application no longer clears unrelated escalations for the same candidate. See [Escalations](/recruiter/escalations).
- **Interview requests close once a booking is confirmed.** A completed booking left its interview request open, so the candidate could still look like they were waiting on times.
- **Resumes with spaces in the file name download again.** See [Applicants](/recruiter/applicants).
- **The escalation inbox loads for every signed-in user.** See [Command Center](/recruiter/command-center).
- **Turning the meeting notetaker off keeps it off.** Saving an unrelated setting could switch it back on.

## July 2026

### New features

- **Calendly bookings are canceled and rescheduled through Calendly.** When a booking was made through a Calendly link, Maigrate now cancels and reschedules it through Calendly's own API rather than editing the calendar event directly. The two systems stop disagreeing about the state of an interview. See [Calendly setup](/integrations/calendly).
- **Meeting links are resolved at send time.** Every message that carries a meeting link now looks the link up when the message goes out, so a candidate can no longer receive a link that changed after the invite was written. See [Scheduling](/recruiter/scheduling).
- **Document review is driven by your own document definitions.** You now define which documents your organization accepts, what each one has to prove, and which of them a given role requires — separately from one another. A document can be valid on its own without satisfying a requirement, which is how expiring credentials and role-specific paperwork actually behave. See [Document review](/settings/document-review).
- **The screening agent can assign a recruiter.** When screening advances a candidate, it can now pick the recruiter to hand them to instead of leaving the assignment for a person. See [Screening](/recruiter/screening).
- **Rejection emails send in every location.** Rejection notices were only going out for one state's postings; they now send everywhere the setting is enabled. See [Communication settings](/settings/communication).

### Updates

- **Blocking escalations can't be pushed out of view.** Command Center's queue limits could hide an escalation that was blocking the agent. Blocking escalations now always appear. See [Command Center](/recruiter/command-center).
- **Every agent can see the screening result.** The communication, document, and scheduling agents now read the candidate's screening context, so they stop asking about things screening already established. See [Screening](/recruiter/screening).
- **Clear escalations in bulk.** A button in Command Center clears resolved escalations without going through them one at a time. See [Command Center](/recruiter/command-center).
- **Private calendar events stay private.** The recruiter calendar page shows a busy block for events marked private instead of their details. See [Recruiter settings](/settings/recruiters).
- **No same-day morning confirmation for a same-day booking.** If a candidate books an interview on the day it happens, the morning confirmation is skipped.
- **Twilio's inbound webhook configures itself.** Connecting Twilio now sets the inbound SMS webhook URL for you. See [Twilio integration](/integrations/twilio).
- **The applicant list is paginated and loads faster.** See [Applicants](/recruiter/applicants).
- **"Interested - Not Scheduled" is retired.** The status never meant anything distinct from the statuses either side of it.
- **Salesforce records an end date for inactive contacts.** A contact moved to an inactive onboarding step now gets its end date set at the same time. See [Salesforce integration](/integrations/salesforce).
- **Integration tokens are scoped and revocable.** An API token issued to an integration now reaches only that integration's endpoints, and it stops working as soon as the tenant is disabled. Recruiter management endpoints are admin-only.

### Bug fixes

- **A stalled follow-up loop left candidates uncontacted.** Fixed a case where the follow-up cadence retried hourly without ever sending anything or giving up, which stranded a small number of candidates who were never contacted and never retired. See [Follow-up policy](/recruiter/follow-up-policy).
- **No-show applications no longer retry forever.** Outreach after a no-show did not count against the follow-up limit, so it repeated indefinitely.
- **Notes to the agent are no longer logged as texts to the candidate.** Guidance a recruiter typed for the agent could appear in the candidate's history as a delivered SMS. See [Communication](/recruiter/communication).
- **Calendly self-bookings write their status back to your ATS.** An interview a candidate booked through a Calendly link never updated the Salesforce record. See [Salesforce integration](/integrations/salesforce).
- **One unreadable calendar no longer blocks scheduling.** If a recruiter's calendar could not be read, the agent stopped looking for times entirely. It now skips that recruiter and carries on.
- **Resumes submitted as images are screened.** A photographed or scanned resume was sent to the screener in a form it could not read. See [Screening](/recruiter/screening).
- **Screening reads the job posting.** Applications arriving from ApplicantStack were screened without the posting they applied to.
- **Meeting invitation subject lines use the right time zone.** See [Scheduling](/recruiter/scheduling).
- **The agent stops asking about documents you already have.** A clarification request could go out for a requirement that had already been satisfied. See [Document review](/settings/document-review).
- **Escalations open the standard detail view.** See [Escalations](/recruiter/escalations).

## June 15-30, 2026

### New features

- **One conversation per candidate, across every application.** Communication is now organized around the candidate rather than around a single application. A candidate who applies to three roles has one thread, one follow-up cadence, and one place their replies land, no matter which application prompted the message. The application pane shows that full conversation. See [Communication](/recruiter/communication).
- **A screening review screen.** Screening results now have their own view, with the model's reasoning, the evidence it used, and the decision it reached — plus the ability to override it. See [Screening](/recruiter/screening).
- **ApplicantStack integration.** Maigrate can now read candidates, applications, and job postings from ApplicantStack, screen them, and write status back. Connect it in Settings and choose which postings to admit by department and location.
- **Recruiter pools.** Recruiters can be grouped into a pool, and the scheduling agent can book a candidate with any recruiter in that pool rather than only the one they were assigned. See [Scheduling settings](/settings/scheduling).
- **Screening criteria can differ by state.** Requirements that vary by location — certification, licensure, minimum hours — can now be expressed per state instead of as one global rule. See [Screening settings](/settings/screening).
- **An admin console for user assignment.** Admins can add, remove, and assign users to the app themselves instead of filing a request. See [Recruiter settings](/settings/recruiters).
- **See the resume in the Documents tab.** A candidate's resume now renders inline alongside their other documents. See [Applicants](/recruiter/applicants).

### Updates

- **The assigned recruiter locks once an interview is booked.** Changing it afterwards left the interview on the wrong person's calendar, so the field is now read-only from that point.
- **Candidates are told when their meeting link changes.** If an interview's link changes after the invite went out, the agent sends the new one rather than leaving the candidate with a dead link. See [Scheduling](/recruiter/scheduling).
- **The agent stops re-asking for credentials it already has.** See [Communication](/recruiter/communication).
- **Faster first follow-up.** The follow-up scan now runs every five minutes, which makes a ten-minute first nudge possible. See [Follow-up policy](/recruiter/follow-up-policy).
- **A rejected document goes to a person.** When the document agent rejects a document, it escalates rather than continuing to ask the candidate. See [Document review](/settings/document-review).

### Bug fixes

- **Calendly bookings get their morning reminder.** Interviews booked through a Calendly link were skipped by the reminder that goes out the morning of. See [Calendly setup](/integrations/calendly).
- **Initial outreach sends reliably.** Fixed a case where the first message to a new candidate failed to go out.
- **Interviews always carry a meeting link.** Fixed a case where an interview was created without one.
- **Scheduling messages are no longer silently dropped.** A message the scheduling agent produced could be recorded without ever being sent.
- **Scheduling escalates when no recruiter is eligible.** Instead of failing quietly, the agent now raises it. See [Escalations](/recruiter/escalations).
- **Screening falls back to the resume text.** If the resume file itself cannot be opened, screening now reads the extracted text rather than giving up. See [Screening](/recruiter/screening).
- **Follow-up attempts count what was actually sent.** The attempt counter incremented on runs that sent nothing, so candidates ran out of follow-ups early.
- **Calendly bookings match the right candidate.** Fixed a case where a booking made with a different email address than the application did not attach to that candidate. See [Calendly setup](/integrations/calendly).
- **Resolving an escalation from the inbox clears it everywhere.** The candidate could stay marked as human-owned after the escalation was resolved. See [Escalations](/recruiter/escalations).
- **Communication template settings save again.** See [Communication settings](/settings/communication).

## Week of June 8, 2026

### New features

- **Full Lumary status sync, including automatic inactive moves.** Maigrate now keeps the complete set of candidate statuses in sync with Lumary/Salesforce and moves candidates to an inactive status on its own when they're no longer active in the process — so your ATS reflects reality without manual cleanup. See [Salesforce integration](/integrations/salesforce).

### Updates

- **Choose what happens after a no-show.** When you mark a candidate as a no-show, you now pick the outcome — reschedule the candidate or reject the application — and the agent takes it from there. See [Interview Agenda](/recruiter/agenda).
- **Calendar availability settings are now per-person.** Each recruiter sees and edits only their own calendar availability, so one person's settings can't be changed by someone else. See [Recruiter settings](/settings/recruiters).

### Bug fixes

- **Rescheduled interviews no longer show the candidate's live link as "canceled."** Fixed a case where, after a reschedule, a candidate's Google Meet link could display the old, canceled event — which in one instance led a candidate to leave a live interview. Rescheduled interviews now keep a clean, correct invite. See [Scheduling](/recruiter/scheduling).

## Week of June 1, 2026

### New features

- **Calendly scheduling, end to end.** You can now connect Calendly in Settings — with a guided setup and a live connection status — and copy an assigned recruiter's Calendly booking link straight from the application drawer. Once connected, Maigrate automatically picks up Calendly bookings, cancellations, and reschedules and keeps each interview's status in sync. Duplicate Calendly bookings no longer silently overwrite an active interview; anything ambiguous is routed for a person to review. See [Calendly setup](/integrations/calendly).
- **Cancel an interview and see full interview history from the drawer.** You can now cancel a scheduled interview directly from the application drawer, and view every interview record for an application — the active one alongside canceled and rescheduled history. See [Scheduling](/recruiter/scheduling).

### Updates

- **Mark a no-show for interviews that already passed.** You can now record a no-show from the application drawer for an interview whose scheduled time has already gone by. See [Scheduling](/recruiter/scheduling).
- **Cancel even when there's no open slot.** If a recruiter's calendar is full, the agent can now cancel a candidate's existing interview without an immediate replacement and keep the candidate in active scheduling, so it continues working to find a new time.
- **Reminders stop for canceled interviews.** Interview reminder and confirmation follow-ups now stop automatically when the related interview is canceled.
- **Stronger separation between organizations.** Every application is now tied to your organization, adding another safeguard that keeps each customer's data fully separate.

### Bug fixes

- **No-shows now show as "Interview Disrupted" in your ATS.** Fixed a case where a no-show didn't roll up to the correct "Interview Disrupted" status in Lumary/Salesforce. See [Salesforce integration](/integrations/salesforce).
- **More reliable ATS status updates.** Status changes now write back to Salesforce/Lumary reliably again, and two updates for the same candidate at the same time no longer overwrite each other.
- **No more duplicate interview invites.** The agent no longer sends duplicate calendar invites for the same interview.
- **No more duplicate documents.** Re-uploading or re-processing the same document no longer creates a duplicate record.
- **Saving one setting no longer affects others.** Fixed a case where saving a screening setting could overwrite a recruiter's saved search configuration.

## Week of May 25, 2026

### New features

- **Interview Agenda — see every interview and its outcome, day by day.** A new agenda screen lets you pick any day — yesterday, today, tomorrow, or any date — and see every interview booked for it, not just the ones still upcoming. Each row shows the candidate's name and email, the recruiter, the current status (confirmed, completed, no-show, canceled, or rescheduled), whether the reminder went out, and the candidate's latest message. You can mark an interview **Completed** or **No-Show** right from the row, and the agent takes it from there. See [Interview Agenda](/recruiter/agenda).
- **Duplicate candidates are handled automatically.** When the same person applies more than once, Maigrate now recognizes them by email and keeps a single candidate record instead of creating duplicates. That means no more doubled-up texts and emails, and candidate replies always route to the right person — while each individual job application is still tracked on its own. See [Applicants](/recruiter/applicants).

### Updates

- **Reschedules keep the same video link.** When an interview is moved, the Google Meet link stays the same, so candidates and interviewers can reuse the original invite. See [Scheduling](/recruiter/scheduling).
- **Canceled interviews stay on the calendar.** Instead of disappearing, canceled and rescheduled interviews now remain on the calendar marked as canceled, so there's always a clear record of what happened.
- **Automatic withdrawal handling.** When a candidate withdraws, the agent now cleans up their scheduling and updates your ATS on its own — no manual follow-up needed. See [Escalations](/recruiter/escalations).

### Bug fixes

- **No more duplicate interview reminders.** Fixed an issue where a candidate could occasionally receive the same interview reminder twice.
- **More accurate scheduling availability.** Calendar events marked as "free" are no longer treated as busy when the agent looks for interview slots, so it offers the right openings.

## Week of May 18, 2026

### New features

- **Candidates can update their contact info by reply.** If a candidate writes back asking you to use a different email or phone number, the agent now recognizes the request and updates their contact details automatically — no recruiter intervention needed. See [Communication](/recruiter/communication).
- **Natural-language no-show handling.** Recruiters can now tell the agent a candidate didn't show up in plain English (for example, "She no-showed her interview") and the no-show workflow will trigger — you no longer have to click the no-show button. See [Escalations](/recruiter/escalations).
- **App-level permissions with admin and user roles.** Tenant sign-in is now restricted to users explicitly assigned to the app, and each user is given either an `admin` or `user` role enforced across the backend and UI. See [Recruiter settings](/settings/recruiters).
- **Download documents from the document center.** You can now download any candidate document directly from the document center, alongside the existing delete action. Click a thumbnail to open a larger preview. See [Document review](/settings/document-review).

### Updates

- **Application link in Google Calendar invites.** Interview invites now include a direct link to the candidate's application in Maigrate, so interviewers can jump straight to context from the calendar event. See [Scheduling](/recruiter/scheduling).
- **Per-tenant Twilio configuration.** Twilio account SID, auth token, and sending number are now configured per tenant instead of shared globally, so each org can use its own number for SMS outreach. See [Twilio integration](/integrations/twilio).

### Bug fixes

- **Same-day interview reminders.** Fixed a regression where AM interview reminders occasionally didn't send during the morning reminder window. Reminders now go out reliably.
- **Legitimate SMS replies no longer blocked as duplicates.** Fixed an issue where a real candidate reply during active scheduling outreach could be incorrectly skipped by the duplicate-send guard.
- **Stale calendar events on candidate withdrawal.** When a candidate withdraws, calendar event cancellation failures are now retried and surfaced instead of being silently swallowed, so interviews don't get left on recruiter calendars.
- **Long emails no longer fail to store.** Very large email threads that previously hit storage limits are now handled correctly and remain fully visible in the candidate's communication history.
