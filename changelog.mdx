## Week of June 1, 2026

### New features

- **Calendly scheduling, end to end.** You can now connect Calendly in Settings — including webhook setup and a live connection status — and copy an assigned recruiter's Calendly booking link straight from the application drawer. Once connected, Maigrate automatically processes Calendly booked, canceled, and rescheduled events and keeps the interview state in sync. Duplicate Calendly bookings no longer silently overwrite an active interview; ambiguous cases are routed for follow-up. See [Scheduling](/recruiter/scheduling).
- **Cancel an interview and see full interview history from the drawer.** You can now cancel a scheduled interview directly from the application drawer, and view every interview record for an application — the active one alongside canceled and rescheduled history. See [Scheduling](/recruiter/scheduling).

### Updates

- **Mark a no-show for interviews that already passed.** You can now record a no-show from the application drawer for an interview whose scheduled time has already gone by. See [Scheduling](/recruiter/scheduling).
- **Cancel even when there's no open slot.** If a recruiter's calendar is full, the agent can now cancel a candidate's existing interview without an immediate replacement and keep the candidate in active scheduling, so it continues working to find a new time.
- **Reminders stop for canceled interviews.** Interview reminder and confirmation follow-ups now stop automatically when the related interview is canceled.
- **Org-scoped data access.** Every application read and write is now scoped to your organization, an added safeguard on tenant data isolation.

### Bug fixes

- **No-shows now show as "Interview Disrupted" in your ATS.** Fixed a case where a no-show didn't roll up to the correct "Interview Disrupted" status in Lumary/Salesforce. See [Salesforce integration](/integrations/salesforce).
- **More reliable ATS status updates.** Restored a Salesforce/Lumary status writeback regression, and concurrent status changes for the same candidate no longer overwrite each other.
- **No more duplicate interview invites.** The agent no longer sends duplicate calendar invites for the same interview.
- **Document uploads are idempotent.** Re-processing the same document no longer creates duplicate records.
- **Saving settings no longer overwrites other fields.** Fixed a case where saving the completion setting could overwrite the recruiter's saved search configuration.

## Week of May 25, 2026

### New features

- **Interview Agenda — see every interview and its outcome, day by day.** A new agenda screen lets you pick any day — yesterday, today, tomorrow, or any date — and see every interview booked for it, not just the ones still upcoming. Each row shows the candidate's name and email, the recruiter, the current status (confirmed, completed, no-show, canceled, or rescheduled), whether the reminder went out, and the candidate's latest message. You can mark an interview **Completed** or **No-Show** right from the row, and the agent takes it from there. See [Interview Agenda](/recruiter/agenda).
- **Duplicate candidates are handled automatically.** When the same person applies more than once, Maigrate now recognizes them by email and keeps a single candidate record instead of creating duplicates. That means no more doubled-up texts and emails, and candidate replies always route to the right person — while each individual job application is still tracked on its own. See [Applicants](/recruiter/applicants).

### Updates

- **Reschedules keep the same video link.** When an interview is moved, the Google Meet link stays the same, so candidates and interviewers can reuse the original invite. See [Scheduling](/recruiter/scheduling).
- **Canceled interviews stay on the calendar.** Instead of disappearing, canceled and rescheduled interviews now remain on the calendar marked as canceled, so there's always a clear record of what happened.
- **Automatic withdrawal handling.** When a candidate withdraws, the agent now cleans up their scheduling and updates your ATS on its own — no manual follow-up needed. See [Escalations](/recruiter/escalations).

### Bug fixes

- **No more duplicate interview reminders.** Fixed an issue where a candidate could occasionally receive the same interview reminder twice.
- **More accurate scheduling availability.** Calendar events marked as "free" are no longer treated as busy when the agent looks for interview slots, so it offers the right openings.

## Week of May 18, 2026

### New features

- **Candidates can update their contact info by reply.** If a candidate writes back asking you to use a different email or phone number, the agent now recognizes the request and updates their contact details automatically — no recruiter intervention needed. See [Communication](/recruiter/communication).
- **Natural-language no-show handling.** Recruiters can now tell the agent a candidate didn't show up in plain English (for example, "She no-showed her interview") and the no-show workflow will trigger — you no longer have to click the no-show button. See [Escalations](/recruiter/escalations).
- **App-level permissions with admin and user roles.** Tenant sign-in is now restricted to users explicitly assigned to the app, and each user is given either an `admin` or `user` role enforced across the backend and UI. See [Recruiter settings](/settings/recruiters).
- **Download documents from the document center.** You can now download any candidate document directly from the document center, alongside the existing delete action. Click a thumbnail to open a larger preview. See [Document review](/settings/document-review).

### Updates

- **Application link in Google Calendar invites.** Interview invites now include a direct link to the candidate's application in Maigrate, so interviewers can jump straight to context from the calendar event. See [Scheduling](/recruiter/scheduling).
- **Per-tenant Twilio configuration.** Twilio account SID, auth token, and sending number are now configured per tenant instead of shared globally, so each org can use its own number for SMS outreach. See [Twilio integration](/integrations/twilio).

### Bug fixes

- **Same-day interview reminders.** Fixed a regression where AM interview reminders occasionally didn't send during the morning reminder window. Reminders now go out reliably.
- **Legitimate SMS replies no longer blocked as duplicates.** Fixed an issue where a real candidate reply during active scheduling outreach could be incorrectly skipped by the duplicate-send guard.
- **Stale calendar events on candidate withdrawal.** When a candidate withdraws, calendar event cancellation failures are now retried and surfaced instead of being silently swallowed, so interviews don't get left on recruiter calendars.
- **Long emails no longer fail to store.** Very large email threads that previously hit storage limits are now handled correctly and remain fully visible in the candidate's communication history.
